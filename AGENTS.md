# Работа над CORE docs

## Назначение

Сопровождать документацию Core: HTML-мануал, Markdown-справочник для агента и примеры. Не менять исходный фреймворк и сторонние проекты в рамках задачи документации.

## Локальный workspace

Если рядом с checkout доступны `../project-kb/project.json` и `../project-kb/AGENTS.md` (например, в `CORE/github-core-docs`), сначала прочитайте `../AGENTS.md` и `../project-kb/AGENTS.md`, затем настройки и текущую задачу в `../project-kb`. Эти материалы принадлежат локальному workspace и не входят в репозиторий.

При самостоятельном clone используйте этот файл и явную задачу пользователя. Отсутствие внешней базы знаний не должно ломать будущую сборку или просмотр документации.

## Правила содержания

- Источник истины — конкретные исходники Core и проверенное поведение примеров.
- Не придумывайте классы, API и ограничения по аналогии с названиями.
- Отличайте штатную возможность, составной рецепт и дополнительный CSS/JS примера.
- Согласуйте HTML и Markdown; ограничения описывайте рядом с механизмом.
- Подключайте штатные ассеты Core из `https://cdn.sdelal.tech/core/latest/`; фиксируйте URL, версию и SHA-256 проверенных ответов в манифесте. Не храните локальный снимок чужого проекта в репозитории.
- Не переносите неподтверждённые выводы о Core из старого сравнения с NKUI как установленные факты.
- Пишите по-русски, кратко и предметно. Точные имена API и классов сохраняйте.

## Структура

Исходники находятся в `content/`: главы в `content/chapters/`, примеры и метаданные в `content/reference/`, JavaScript оболочки в `content/viewer/`. `content/AGENTS.md` адресован потребителю Core, этот файл — автору документации.

`docs/` полностью генерируется командой `npm run build` и исключён из Git. Сборка очищает этот каталог, загружает CSS документированной версии с CDN в память, сверяет SHA-256 и создаёт HTML, публичные Markdown и JSON-справочники. Не редактируйте результат и не сохраняйте копии Core. Служебные инструменты находятся в `tools/`.

Не добавляйте собственный CSS оболочки или примеров. Используйте существующие классы и документированные переменные Core. JS отвечает только за поведение и технические размеры через штатные переменные. Новые версии проверяются командой `npm run check:upstream` только по запросу владельца; расписания нет.

## Проверка изменений

Для текста и инфраструктуры: проверить относительные ссылки, подготовленный diff и `git diff --check`. `npm test`, `npm run test:browser` и `npm run test:layout` запускаются после сборки. Контрактные тесты сверяют CDN с манифестом, браузерные проверяют настоящий latest. Сеть обязательна; ошибку CDN не обходить локальной подменой. Отчёт предыдущего исполнителя не заменяет собственную проверку.

Обновление документации выполняйте по [UPDATE.md](UPDATE.md): сначала `docs:diff`, затем только затронутые главы и примеры. Глобальные и непокрытые изменения требуют явного разбора; номер принятой версии не меняйте ради зелёной проверки.
