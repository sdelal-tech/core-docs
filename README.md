# Core — документация

[Открыть мануал](https://github.sdelal.tech/core-docs/) · [Markdown для агента](content/AGENTS.md) · [Источники и проверки](content/chapters/verification.md)

42 раздела, 87 примера. Документированная версия и дата — в [манифесте](content/reference/source-manifest.json); сайт выводит их из этого же источника. Оболочка и примеры используют штатные темы и токены Core без собственных CSS-правил. В шапке доступны Core, NK, SS и NKUI; оформление и светлый/тёмный режим выбираются отдельно. Обрамление примеров и код используют противоположный светлый/тёмный режим, а содержимое iframe сохраняет выбранный. Штатные `--w`, `--h` и `--tr` задают размер и масштаб примеров.

После `npm run build` откройте `docs/index.html` в браузере или используйте опубликованный мануал по ссылке выше. Сам файл статический; оформление, шрифты и живые примеры требуют сети. Runtime использует CDN `latest`, поэтому его содержимое со временем может отличаться от проверенной версии.

Боковая навигация сохраняет группы и подразделы; шапка с поиском закреплена. На экранах до 997 px разделы открываются поверх статьи. Меню закрывается по Escape, нажатию на фон или выбору раздела. Поиск доступен по ⌘K / Ctrl+K.

У примера семь кнопок ширины: Auto, 390, 720, 721, 997, 998 и 1200 px. HTML и JavaScript всегда видны сразу под результатом, каждый блок можно скопировать. Тема, ввод и выбранная ширина сохраняются при переключении глав в открытом мануале. Оформление и светлый/тёмный режим также сохраняются в localStorage после перезагрузки. Код подсвечивается при сборке; копирование сохраняет исходный текст.

## Редактирование

- `content/chapters/` — тексты глав; индекс классов генерируется при сборке.
- `content/reference/examples.json` — разметка и JavaScript примеров. При изменении примера обновите соответствующий блок Markdown; проверка сверяет их.
- `content/reference/` — JS-контракты и метаданные проверенной версии: URL, размеры и SHA-256. Копии исходного Core в репозитории не хранятся.
- `content/chapters.json` — порядок, группы и короткие названия разделов.
- `content/viewer/` — поведение оболочки и выбор тем, без собственного оформления.
- `tools/` — сборка и инспекция CDN; `tests/` — проверки.
- `docs/` — полностью генерируемый результат, исключённый из Git: HTML, публичные Markdown и JSON. Не редактируйте его вручную.

Node.js 22 или новее и Python 3 нужны только для разработки и сборки. Зависимости закреплены в lockfile: Marked разбирает Markdown, Highlight.js подсвечивает код при сборке, PostCSS и selector-parser строят справочники, Playwright проверяет настоящий браузер. Стандартный `zipfile` Python собирает агентский архив без дополнительных пакетов. Runtime не использует npm-пакеты.

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run test:layout
npm run serve
```

Локальный адрес: `http://127.0.0.1:4173/`. Тесты используют Chromium, совместимый с закреплённым Playwright. Установка браузера нужна один раз после `npm ci`. Справочники собираются из пяти CSS-файлов документированной версии с CDN после проверки SHA-256. Контрактные тесты проверяют все файлы манифеста и доступность latest. Недоступность CDN или неверный хеш документированной версии останавливает проверку; изменение latest выводится диагностикой и не принимается автоматически.

Браузерные тесты проверяют мануал с настоящим latest, включая iframe и ESM. Точные CSS-контракты дополнительно проверяются на версии из манифеста. Внизу навигации показаны версия Core и дата обновления документации из `documentation_updated_at` в манифесте; обновляйте это поле при изменении публикуемого руководства. Дата сравнения latest и его результат остаются в манифесте; это отдельная проверка, а не обещание неизменности канала.

`npm run test:layout` проверяет компактность шапки, неподвижность боковой панели, меню без сдвига статьи, клавиатурный фокус и структуру примеров на граничных ширинах. Визуальную аккуратность дополнительно проверяйте по парным снимкам: функциональный прогон её не доказывает.

`npm run build` очищает `docs/`, копирует публичные исходники, генерирует каталоги классов/токенов и индекс классов из CDN, создаёт `docs/core-agent.zip`, затем собирает HTML. В ZIP входит папка `core/` с `AGENTS.md`, README, оглавлением, всеми Markdown-главами и JSON-справочниками. Ссылки на файлы документации внутри архива относительные; HTML, runtime Core и инструменты сборки исключены.

В Git коммитятся только исходники. GitHub Actions выполняет ту же сборку и проверки перед публикацией Pages, поэтому ZIP обновляется вместе с сайтом. Скачивание и инструкция подключения доступны в разделе [«Работа с агентом»](https://github.sdelal.tech/core-docs/#agent-workflow). Служебные инструменты и исходник просмотрщика в артефакт не копируются; JavaScript просмотрщика встроен в HTML.

`python3 tools/inspect-cdn.py --audit` читает и хеширует текущие JS-файлы CDN без сохранения локальных копий. Проверка сетевых отказов мануала входит в обычный браузерный прогон.

## Обновление Core

Проверять новые версии **только по запросу владельца**:

```sh
npm run check:upstream
npm run docs:diff -- --to latest
```

`check:upstream` ничего не меняет: сравнивает каталог версий, список файлов latest и SHA-256 каждого файла с манифестом. Код выхода: 0 — совпадает, 2 — есть изменения, 1 — ошибка проверки. `docs:diff` фиксирует выбранную версию, проверяет исходную базу и сохраняет компактный отчёт, изменения API, связи с главами и кандидат манифеста в игнорируемом `work/core-update/`. Принятие версии выполняется после разбора и проверок. Подробный процесс — в [UPDATE.md](UPDATE.md). Обычные сборки и проверки не обновляют эту базу автоматически.
