# Core — документация

Репозиторий собирает два статических результата из одних исходников: HTML-мануал для чтения в браузере и ZIP с Markdown/JSON-справочником для агента. В мануале 42 раздела и 87 живых примеров. [Открыть мануал](https://github.sdelal.tech/core-docs/) · [Инструкция агента](content/AGENTS.md) · [Источники и проверки](content/chapters/verification.md).

Мануал работает в браузере: CSS и JavaScript-модули Core, шрифты и живые примеры загружаются из сети с CDN `latest`. В оболочке доступны темы Core, NK, SS и NKUI; тему оформления и светлый/тёмный режим можно выбирать отдельно. Панель примера и код используют противоположный режим, а iframe сохраняет выбранную тему. Примеры выполняются в sandbox-iframe с разрешением `allow-scripts`. Штатные переменные `--w`, `--h` и `--tr` задают ширину, высоту и масштаб.

Навигация группирует главы и подразделы, закреплённая шапка содержит поиск. На экранах до 997 px меню открывается поверх статьи и закрывается по Escape, нажатию на фон или выбору главы. Поиск открывается по ⌘K / Ctrl+K. Каждый пример имеет семь вариантов ширины: Auto, 390, 720, 721, 997, 998 и 1200 px. HTML и JavaScript видны под примером и копируются отдельными блоками. Тема, ввод и ширина сохраняются при переходе между главами; тема и режим также сохраняются в `localStorage` после перезагрузки. Код подсвечивается при сборке, при копировании берётся исходный текст.

```text

│   ├── chapters/             главы в Markdown
│   ├── reference/            примеры, API-справочники и CDN-манифест
│   ├── viewer/               JavaScript оболочки
│   ├── AGENTS.md             инструкции для потребителя Core
│   ├── chapters.json         порядок и названия глав
│   └── README.md             оглавление и вводное руководство
├── tools/                    сборка, справочники и анализ обновлений
├── tests/                    контрактные, браузерные и layout-проверки
├── .github/workflows/        CI и публикация Pages
├── docs/                     сайт и агентский ZIP после сборки (ignored)

Каталоги `node_modules/`, `test-results/` и `work/` содержат локальные установленные инструменты и рабочие результаты, исключённые через `.gitignore`. `work/core-update/` может содержать подготовленные отчёты анализа, но не входит в сайт.

## Исходники

`content/` — источник публичного мануала. `content/chapters/` хранит тексты глав; `content/chapters.json` задаёт их порядок, группы и короткие названия. `content/README.md` служит оглавлением и вводным руководством, а `content/AGENTS.md` описывает комплект для потребителя Core. Корневой `AGENTS.md` относится к редактированию самой документации; это разные аудитории.

`content/reference/examples.json` содержит канонические HTML и JavaScript всех примеров. Маркер в главе связывает пример с местом показа; тест сверяет соседние блоки Markdown с JSON, чтобы HTML для человека и источники живого iframe оставались согласованными. `javascript.json` описывает JS API. `cdn.json` перечисляет модули и CDN-метаданные. Копии исходников Core в репозитории не хранятся.

`source-manifest.json` содержит принятую версию, даты проверки и обновления документации, URL и SHA-256 проверенных CSS, JavaScript и HTML-файлов в `version_files`, а также данные сравнения с runtime CDN. Это закреплённая база справочников. Сайт и живые примеры при этом загружают Core CSS с изменяемого канала `latest`; его содержимое может отличаться от манифеста. Не считайте `latest` неизменяемой версией.

`content/viewer/app.js` отвечает за навигацию, поиск, мобильное меню, копирование блоков, sandbox-iframe, загрузку примеров и размеры. `themes.js` переключает оформление и светлый/тёмный режим. Оболочка использует классы и переменные Core. Подсветка открываемой главы выполняется на клиенте Highlight.js 11.11.1 со штатными a11y-light/dark CSS; эта библиотечная CSS-тема ограничена блоками кода и переключается в противоположный режим. Инверсные блоки принимают шрифты и метрики своей темы. При недоступной подсветке исходный код остаётся читаемым, навигация и копирование работают.

## Инструменты

| Файл или команда | Назначение |
| --- | --- |
| `tools/build.mjs` / `npm run build` | Очистить `docs/` и собрать HTML-мануал со справочниками и ZIP |
| `tools/references.mjs` | Построить индексы классов, токенов и классов из примеров на основе пяти CSS-файлов закреплённой версии |
| `tools/cdn.mjs` | Загрузить CDN-источник в память и проверить его SHA-256 |
| `tools/highlight.mjs` | Экранировать код, обозначить язык и собрать pinned браузерный Highlight.js с пятью грамматиками и штатными CSS-темами |
| `tools/package-agent.py` | Создать ZIP для агента стандартной библиотекой Python |
| `tools/check-upstream.mjs` / `npm run check:upstream` | Сравнить текущий каталог CDN `latest` с манифестом без принятия изменений |
| `tools/docs-diff.mjs`, `tools/update-diff.mjs` / `npm run docs:diff` | Подготовить отчёт изменений и кандидата манифеста для выбранной версии |
| `tools/update-dependencies.json` | Связать исходные CSS/JS/HTML-файлы Core с темами и главами при анализе обновлений; это не npm-зависимости |
| `tools/inspect-cdn.py --audit` | Проверить и захешировать текущие JS-файлы CDN без сохранения копий |

## Сборка

`npm run build` выполняет следующие шаги:

1. Полностью пересоздаёт `docs/` и копирует туда публичные README, инструкции потребителя, оглавление, главы и JSON-справочники из `content/`.
2. Загружает в память пять CSS-файлов закреплённой версии — `core.css` и четыре файла тем. Сверяет SHA-256 ответов и использует PostCSS с разборщиком селекторов для `reference/classes.json`, `reference/tokens.json` и `chapters/class-index.md`. Сами CSS-файлы не записываются в результат.
3. `tools/package-agent.py` создаёт `docs/core-agent.zip`. Архив содержит папку `core/` с инструкцией потребителя, README, оглавлением, Markdown-главами и JSON-справочниками. Ссылки внутри архива становятся относительными. HTML-просмотрщик, Core runtime и сборочные инструменты в ZIP не входят.
4. Сборщик объединяет главы в один `docs/index.html`, строит навигацию и поисковый индекс, вставляет канонические примеры, подсвечивает код, затем встраивает данные и JavaScript оболочки.

Результат — статические HTML, Markdown и JSON плюс ZIP. Отдельный frontend-бандлер не используется. Сборка не публикует сайт и не обновляет принятую версию Core. `docs/` генерируется заново, поэтому не редактируйте его вручную.

## Зависимости и node_modules

Node.js 22 или новее и Python 3 нужны для разработки, сборки и проверок; посетителю уже собранного сайта они не нужны. Прямые npm-пакеты объявлены как `devDependencies` в `package.json`:

| Пакет | Версия | Использование |
| --- | --- | --- |
| `marked` | `17.0.5` | Преобразование глав из Markdown в HTML |
| `highlight.js` | `11.11.1` | Клиентская подсветка кода |
| `postcss` | `8.5.6` | Разбор CDN CSS для справочников |
| `postcss-selector-parser` | `7.1.0` | Извлечение имён CSS-классов |
| `playwright` | `1.62.1` | Запуск браузерных проверок |

| Файл или каталог | Что в нём |
| --- | --- |
| `package.json` | npm-команды, имя проекта и прямые dev-зависимости |
| `package-lock.json` | Полное точное дерево, включая транзитивные npm-пакеты |
| `node_modules/` | Установленные локальные пакеты из дерева lockfile; игнорируется Git |
| Кэш Playwright | Установленный отдельно Chromium для браузерных проверок |

`npm ci` удаляет и восстанавливает `node_modules/` по lockfile, поэтому подходит для повторяемой установки в CI. Удаление `node_modules/` убирает только локальные установленные инструменты: исходники, манифест, lockfile и ранее собранный сайт остаются на месте. Перед следующей сборкой или проверкой достаточно снова выполнить `npm ci`. `npm install` может обновлять lockfile; для обычной подготовки используйте `npm ci`.

Архив и проверка его содержимого используют Python 3 и стандартный модуль `zipfile`; дополнительные Python-пакеты не нужны. Тест распаковывает архив для проверки состава и ссылок. Сборка воспроизводимо включает Highlight.js и его CSS из установленного pinned npm-пакета в `docs/assets/`; браузеру нужна сеть для CSS Core и шрифтов, а примеры изолированы в sandbox-iframe.

## Локальный запуск

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run test:layout
npm run serve
```

После `npm run build` можно открыть `docs/index.html` непосредственно в браузере или запустить `npm run serve` и открыть `http://127.0.0.1:4173/`. Команда запускает стандартный Python `http.server`, который раздаёт каталог `docs/`. В обоих случаях для оформления, шрифтов и живых примеров нужен доступ к сети. Chromium ставится отдельно Playwright и хранится вне `node_modules/`. Для сборки и CDN-проверок требуется доступ к CDN; источник сверяется по хешу, локальная подмена не используется.

## Проверки и публикация

| Команда | Что проверяет |
| --- | --- |
| `npm test` | Контракты структуры и ссылок, примеры в Markdown/JSON, CDN-хеши, подсветку, состав и воспроизводимость ZIP |
| `npm run test:browser` | Взаимодействия в Chromium: навигацию, темы, поиск, iframe и живые примеры с `latest` |
| `npm run test:layout` | Размеры, меню, положение панели, фокус клавиатуры и граничные ширины |

Контрактные тесты используют `node:test`. Точные CSS-контракты проверяются по закреплённому манифесту, браузерная оболочка и примеры — с текущим `latest`. Недоступность CDN или несовпадение хеша закреплённого файла останавливает проверку. Диагностическое отличие `latest` показывается отдельно и не принимается автоматически. `test-results/` хранит временные логи, JSON-отчёты и снимки; результаты не коммитятся. Layout-тесты подтверждают геометрию и работу с клавиатуры, но не заменяют визуальный осмотр снимков.

GitHub Actions запускается при push в `main` или вручную. Workflow использует Node.js 22, выполняет `npm ci`, сборку, устанавливает Chromium, запускает все три набора проверок и только после успеха загружает `docs/` и публикует его через GitHub Pages. Агентский ZIP публикуется вместе с сайтом. `npm run build` локально только готовит артефакт. Изменения одного README можно коммитить с `[skip ci]`, поскольку они не меняют Pages-содержимое.

## Обновление Core

Проверяйте новые версии только по запросу владельца. Рабочий порядок и критерии разбора описаны в [UPDATE.md](UPDATE.md):

```sh
npm run check:upstream
npm run docs:diff -- --to latest
```

`check:upstream` ничего не изменяет. Он сравнивает каталог версий, файлы `latest` и их SHA-256 с манифестом: код выхода `0` означает совпадение, `2` — обнаружены изменения, `1` — ошибка проверки.

`docs:diff` один раз определяет выбранную версию и готовит папку в `work/core-update/` с `report.md`, `report.json`, `api.json` и `candidate-manifest.json`. `report.md` суммирует затронутые файлы и главы; JSON-отчёт хранит детали анализа, `api.json` — изменения API, а кандидат манифеста остаётся предложением. `update-dependencies.json` связывает CSS, JavaScript и HTML Core с темами и главами для поиска влияния изменений. Эти файлы помогают проверить, какие разделы и примеры нужно пересмотреть.

После анализа обновляются только подтверждённые главы, примеры и манифест. Затем нужно пересобрать документацию и запустить проверки; только проверенный результат становится новой закреплённой версией. Обычная сборка и браузерный тест не меняют её автоматически. Исторически исходный комплект v182 сохранён в коммите `e9de771`; последующие обновления отслеживаются в Git.

Runtime-канал `latest`, дата его последней проверки и результат сравнения отражаются в `source-manifest.json`. Это диагностическая отметка времени, а не гарантия неизменности CDN. Внизу навигации показываются закреплённая версия и дата документации из `documentation_updated_at`; обновляйте дату при изменении публикуемого руководства.
